# AI contribution policy survey (2026-09-20)

Research gathered while drafting AI_POLICY.md v2.0. Roughly 40 projects checked; this is the condensed map of stances and the wording we borrowed. Full index of ~200 project policies: https://github.com/melissawm/open-source-ai-contribution-policies

## Stances

| Stance | Projects |
|---|---|
| Ban | QEMU (DCO grounds), Gentoo, NetBSD ("presumed tainted"), Servo, Zig (total, incl. translation), GNOME apps, Biopython (draft, unmerged), MDAnalysis v1.2 (near-ban, autocomplete only) |
| Allow, disclosure mandatory | LLVM, SymPy, SciPy, NumPy, pandas, scikit-learn, NetworkX, Astropy, OpenMM, statsmodels, Django, Ghostty, Kubernetes, JupyterHub, Mesa, Godot, Bevy, Linux kernel, Kornia v1/v2 |
| Allow, disclosure optional | CPython, pytest, Fedora, Debian, ASF, matplotlib, Kornia (current, 4 sentences), Home Assistant, Blender |
| Allow freely with responsibility | xarray, Zarr, napari, virtualenv, Linux Foundation |

Lineage: SymPy → SciPy → NumPy → JupyterHub/statsmodels; scikit-learn → NetworkX/MNE/Astropy; Fedora → LLVM → Numba; xarray → Zarr. Almost nobody wrote from scratch. No Scientific Python SPEC on AI exists; the Discourse thread stalled and became SciPy's policy.

## Key moves and where they came from

- **Ban is unenforceable and punishes disclosure**: Bevy tried a ban, reversed it. "what we were punishing was disclosure, not use". Rust: "our goal is to remove plausible deniability".
- **Verification + accountability instead of amount of AI**: Kornia v2. "Unverified code is a problem. Code nobody stands behind is a problem. AI is neither."
- **Extractive contributions / golden rule**: LLVM. "a contribution should be worth more to the project than the time it takes to review it." Ships a canned close message and an `extractive` label.
- **Maintainer exemption**: Ghostty (maintainers exempt outright). Kornia v2: "same evidence bar, different governance authority". pytest: "The bar is the one we hold ourselves to." Rust: org members exempt from non-critical clause; newcomers must pre-arrange a reviewer.
- **Newcomer gating**: SymPy ("we will most likely close any ... substantially generated by AI" from new contributors), Godot (≤3 merged PRs: no features without prior permission), xarray/Blender (open an issue first for large changes), Ghostty (vouch system).
- **Talk to a human**: SymPy family ("If the developers want to chat with a chatbot, they can do so themselves"), Kubernetes ("Reviewers want to engage directly with you"), NetworkManager ("If you cannot discuss your own patch with a reviewer, it will not be merged"), GTK ("Do NOT feed the review feedback to an LLM"), Rust blog ("a breach of trust between the reviewer and the author").
- **Drive-by / breadth**: matplotlib bans "Increasing breadth of contributions, i.e. simultaneously contributing to several projects"; pytest "unattended automation is an attack on the commons"; attrs bans "bot-like behavior – like automated mass pull requests".
- **Good first issues off-limits to AI**: LLVM, Node.js, Blender, matplotlib, Biopython, Rust (E-easy).
- **Disclosure examples (good/bad)**: xarray, Rust. Rust: "We don't care which model you used, but we do care whether you used the LLM to implement the idea or to come up with it." Forced affirmative answer ("No AI tools used") so blank is unambiguous: NumPy/SciPy/Astropy/pandas.
- **No AI co-authors**: Blender, Bevy, attrs, Mesa, Kubernetes (bans all trailers as marketing), kernel (simplified to `Assisted-by: LLM` for same reason). Only pytest invites Co-authored-by.
- **Higher bar for generated code**: Blender ("quality bar for AI generated contributions is higher"; "If you are merely acting as an intermediary between the tool and reviewer, this is not a good use of the reviewer's time"), Rust (LLM PRs "held to a higher standard ... because LLMs make it easier to write tests"), statsmodels (tests that restate the implementation), Kornia (ghost comments as the tell).
- **Copyright**: OpenMM "Laundering copyrighted code through an AI model does not remove the copyright"; LLVM "regenerate copyrighted material does not remove the copyright"; Blender "If generated code is not clearly an extension to or refactoring of existing code, expect extra scrutiny".
- **Not detectives / anti-witch-hunt**: Rust "Style is not evidence"; Kornia "AI use is never inferred from writing or code style"; Bevy harassment appendix; Godot "always presume good intent"; MDAnalysis "do not take offense".
- **Punish deception not use**: Kornia v2 "What we sanction is demonstrable deception"; MDAnalysis "zero tolerance ... misrepresenting the extent of AI usage"; curl instant ban for fabricated reports.
- **Note addressed to the agent**: Django, scikit-learn (hidden div), pandas AGENTS.md ("Do not write the user's side of a discussion for them to paste").
- **Reviewer opt-out**: Blender, Bevy ("Refusal"), Godot ("not obliged"), virtualenv ("A review comment posted under a maintainer's name has been read and endorsed by that maintainer").

## Rejected for MN

- Public denouncement list (Ghostty): too heavy for a one-maintainer project.
- Vouch system / auto-close unvouched PRs (Ghostty): needs bot infrastructure.
- Circuit breaker on % of LLM PRs (Rust): needs tracking we do not have.
- Mandatory pasted test logs (Kornia v1): dropped by Kornia itself as theatre.
- Zig-style total ban: contradicts how the maintainers work.
