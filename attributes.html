Attributes

Below are the attributes which are potentially created when a structure is imported. Explanations of type and domain conversions can be found in the Blender documentation here

World Scale

In Molecular Nodes, the world scale determines how real-world measurements are translated into the 3D environment of Blender which uses metres. Currently, 1 nanometre (nm) is equivalent to 1 metre (m). Scaling structural coordinates (which are in Å) by 0.1 correctly converts them and 0.1 is referred to as the world_scale.

This changed with Molecular Nodes v520: previously the world scale was 0.01, so 1 Å equalled 1 cm.

When an attribute is going to be read from the geometry, it is colored red like so: Index, chain_id, while when a specific data type is referenced it will be colored according to the data type like so: Int, Float, Vector, etc.

Data Types

Attribute Types

Attributes are always associated with Geometry. They will be stored on one of the domains of the geometry. The type of the attribute is determined by the type of the data it contains. The following types are supported by Geometry Nodes.

Type Description
Int 32-bit integers
Float 32-bit floating point numbers
Bool A simple True or False value
Vector A vector of (x, y, z) values. Can also be 2D, 3D or 4D although support outside of 3D vectors is limited.
Matrix 4x4 floating point matrices, also references as Transform inside of Geometry Nodes
Color Linear RGBA colors, stored as (0..1, 0..1, 0..1, 0..1) values
Rotation A (w, x, y, z) rotation that internally is represented as a quaternion, but can implicitly be converted to an Euler vector.

Other Data Types

Additional data types which are not supported as Attributes but can be used in the node tree are:

Type Description
String String support in Geometry Nodes is limited at the moment and you cannot store strings as attributes
Object Access to objects in the 3D scene and their associated data
Collection Access a collection of objects from the scene. Objects are returned as instances
Material Material to be applied to the created geometry
Menu A menu for selecting a value from a list of options
Image A reference to an image data-block, for sampling or texturing
Shader The output of shader nodes, used when building materials rather than geometry
Bundle New in Blender 5.0: multiple sockets packed together and passed along a single link
Closure New in Blender 5.0: a piece of node tree logic passed around as a value, to be evaluated elsewhere

Attributes

All of the molecular attributes which are defined as strings such as chain_id, res_name, etc. are stored as integers in the geometry because Geometry Nodes does not support string attributes.

How the integer is assigned depends on the attribute. For the dynamic ones the strings are stored as metadata on the object, so an integer can be mapped back to its string (see Reading Attributes from Python):

Attribute Integer assigned from Strings stored in
chain_id Position in the alphabetically sorted list of unique chain IDs mol.props.chain_ids
entity_id Position in the entity category of the file, in file order mol.props.entity_ids
segid Index of the segment, in topology order mol.props.segments
atom_types Position in the sorted list of unique atom types mol.props.atom_type_unique
res_name Fixed lookup table
atom_name Fixed lookup table

Point Attributes

Attribute Type Description
Position Vector Coordinates in 3D space of the points, read from the molecular data file. They are scaled by the world scale 0.1 on import so that 1 nm == 1 m.
b_factor Float The temperature factor for the atom on import. If importing an AlphaFold structure this corresponds to the pLDDT value. For a trajectory whose frames have their own B-factors, such as the models of a multi-model .pdb or .cif file, it is updated on each frame. A file loaded on its own only updates them when they differ between models.
occupancy Float The crystallographic occupancy of the atom, or 0.0 if the file has none. Updated on each frame when the frames have their own occupancies, as for b_factor.
charge Float The charge of the atom, only present when the file or topology provides charges: partial charges from simulation topologies, formal charges from structure files. Updated on each frame from the q column of a LAMMPS dump read with additional_columns.
vdw_radii Float The radii of the atom, stored in world space (~0.15). Values sourced from Wikipedia.
sec_struct Int Defines secondary structure for the residue the atom is part of. 0 for not a protein. 1 for helices, 2 for sheets, 3 for coils / unstructured.
mass Float Mass of the element
chain_id Int Position of the chain ID in the sorted list mol.props.chain_ids. For .cif and .bcif files this is the author chain ID (auth_asym_id), as in .pdb files.
segid Int The index of the segment the atom belongs to, when the topology defines segments. The segment names are stored as metadata on the object.
fragment_id Int The index of the bonded molecule (fragment) the atom belongs to, for structures with bonds. Link it into Group ID of Periodic Unwrap to keep molecules whole.
entity_id Int Multiple chains can be the same entity, if they are copies of the same protein in the structure. Only .cif and .bcif files define entities. Numbered in the file’s order.
res_name Int Residues are mapped to integer values based on the lookup table.
res_id Int The residue number. For .cif and .bcif files this is the author residue number (auth_seq_id), as in .pdb files, so it may not start at 1 for the first residue in each chain.
ures_id Int The ures_id starts at 0 and increases by 1 for each residue across the whole structure, unlike res_id, which follows the file’s numbering within each chain.
atomic_number Int Stores the atomic number of the atom for it’s position on the periodic table, instead of the element’s name.
atom_name Int Atom names are mapped to integer values based on the lookup table.
atom_types Int The force-field atom types from simulation topologies, sorted uniquely and assigned integers on import. The type names are stored as metadata on the object.
Color Color Color of the atom, assigned on import but often changed in node trees.
atom_id Int Unique ascending value for each atom in the file, starting at 1
is_alpha_carbon Bool Whether the atom is an alpha carbon (atom name CA, or BB for coarse-grained structures) of an amino acid residue. Ions and ligands are excluded.
is_side_chain Bool Whether the atom is part of a side chain: an atom of an amino acid or nucleotide residue that is not part of the backbone. The alpha carbon also counts as side chain.
is_backbone Bool Whether the atom is part of the peptide or nucleic backbone, based on its atom name, in amino acid and nucleotide residues. Ions and ligands are excluded.
is_solvent Bool Whether the atom is part of a solvent molecule (such as water), based on its residue and atom names.
is_nucleic Bool Whether the atom is part of a residue MDAnalysis recognises as a nucleic acid.
is_peptide Bool Whether the atom is part of an amino acid residue, including modified residues (such as HIC) and coarse-grained (Martini) BB or SC* beads.
is_lipid Bool Whether the atom is part of a lipid, based on its residue name.
is_hetero Bool Whether the atom is flagged as a hetero atom in the structure file.
is_carb Bool Whether the atom is part of a carbohydrate, based on its residue name.
velocity Vector The velocity of the atom, stored on each frame that has velocities (such as frames of .trr files). Scaled by the world scale like positions, so it is in Blender units per ps (Å/ps × 0.1), and position + velocity gives where the atom heads in 1 ps. Interpolated and averaged between frames like positions. GROMACS can write velocities on only some frames (nstvout): the attribute appears on the first frame with them, and frames without them keep the values last stored. Interpolating towards a frame without them uses the current frame’s values, and averaging uses only the frames that have them.
force Vector The force on the atom, stored on each frame that has forces (such as frames of .trr files). Kept in the MDAnalysis units of kJ/(mol·Å) and not scaled by the world scale, as a force is not a length. Frames without forces (GROMACS nstfout) are handled the same way as for velocity.

Edge Attributes

Bonds between atoms are represented as edges in the geometry, and only the bond type is stored on the edge domain.

Attribute Type Description
bond_type Int The type of bond between the atoms.

Bond types are currently the values used by biotite

Bond Type Integer Value Description
ANY 0 Used if the actual type is unknown
SINGLE 1 Single bond
DOUBLE 2 Double bond
TRIPLE 3 Triple bond
QUADRUPLE 4 A quadruple bond
AROMATIC_SINGLE 5 Aromatic bond with a single formal bond
AROMATIC_DOUBLE 6 Aromatic bond with a double formal bond
AROMATIC_TRIPLE 7 Aromatic bond with a triple formal bond

Attributes by Format

Which attributes are created depends on what the file provides. These attributes are created for every format: position, atomic_number, atom_name, atom_types, res_name, res_id, segid, mass, vdw_radii, b_factor, occupancy, Color and the is_* flags except is_hetero and is_carb. The others vary:

Attribute .pdb .cif / .bcif .sdf / .mol MD topology
chain_id ✓ ✓ ✓
entity_id ✓
ures_id ✓ ✓ ✓
atom_id ✓ ✓ ✓
sec_struct ✓ ✓ ✓
is_hetero ✓ ✓ ✓
is_carb ✓ ✓ ✓
bond_type ✓ ✓ ✓
fragment_id ✓ ✓ ✓ if the topology has bonds
charge if in the file if in the file if in the file if the topology has charges

Simulation topologies differ in what they contain, so the MD column is for typical topologies such as .psf and .gro. Trajectories also get velocity and force once a frame that has them is shown; most trajectory formats, such as .xtc and .dcd, store neither. Other per-atom values that MDAnalysis reads for each frame into ts.data are stored as attributes too: the B-factors and occupancies of each model of a .pdb file (as b_factor and occupancy; a multi-model .pdb, .cif or .bcif file loaded on its own updates them the same way when they differ between models), the additional_columns of a LAMMPS dump (q as charge, others by their column name) and the additional_blocks of a .tng file (by block name). Any other key that is the name of an attribute Molecular Nodes creates on import, such as a LAMMPS mass column, is stored with a ts_ prefix (ts_mass) so it never overwrites that attribute. Float values are interpolated and averaged between frames like positions; integer and boolean values take the current frame’s values. The attributes a trajectory updates on each frame are listed in its Attributes panel, along with its selections, with their source: the trajectory, a selection, or a calculation in Molecule.calculations (such as sec_struct from DSSP, which a trajectory without secondary structure in its files gets on load, run on the first frame and set to update on every frame with mol.calculations.dssp(updating=True) or the toggle in the list, where selecting it shows its settings). Molecule.frame_attributes returns the same list as a dict of name to source. Single-frame structures keep the values from import. mol.list_attributes() lists the attributes on a molecule, and mol.named_attribute() raises an error for one that was not created. In the node tree there is no error: reading a missing attribute gives 0 (or False) for every atom, so selecting by entity_id on a .pdb file treats every atom as entity 0.

Reading Attributes from Python

mol.named_attribute() returns the attribute stored on the object as a numpy array, one value per atom. The integer attributes in the table above can be mapped back to their strings with the stored metadata:

import numpy as np
import molecularnodes as mn

mol = mn.Molecule.fetch("1CD3", format="cif")

chain_id = mol.named_attribute("chain_id")
chain_names = np.array(mol.props.chain_ids)[chain_id]  # e.g. "1", "2", "B"

is_alpha_carbon = mol.named_attribute("is_alpha_carbon")
print(np.unique(chain_names[is_alpha_carbon], return_counts=True))

position is in Blender units, the coordinates in Å scaled by the world scale, for the current frame and before any node tree changes. mol.universe.atoms.positions has the same coordinates in Å.

mol.named_attribute(name, evaluate=True) instead reads the geometry after the node tree is evaluated, which is not one point per atom once a style is applied. A cartoon is a mesh with many more vertices than there are atoms, and spheres are instances by default so the evaluated mesh is empty. To get atom positions, read the stored position or the universe instead of the evaluated geometry.

Domains

Domain Description
Point Individual points of geometry. These can be the vertices in a mesh, the points in a point cloud, or the control points of a curve.
Edge The edges of a mesh, defined as the indices between two points.
Face A face of a mesh, defined as a collection of edges.
Corner Corners of a face, where two edges meet.
Curve A curve object, which contains multiple control points, but can itself store attributes.
Instance Instances are references to other geometry. Instancing is useful for making lots of copies of some geometry for performance.
Layer Layers are for Grease Pencil, and contain a collection of curves.
